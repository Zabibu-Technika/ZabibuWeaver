What it does / 01

MORE THAN A CHAT.
A WORKING LOOP.

Weaver does the whole loop: read, edit, search, run, verify. Then it leaves evidence. It is the opposite of a chat window that says “done” and hopes you believe it.

01

Read / edit / search / run

A real tool loop over your repo. Inspect, change, and execute — with a permission gate on every mutating step.

02

Verify with your checks

package.json scripts, tsc, Cargo, Go, pytest. A failing check goes back to the model once, then the receipt tells the truth.

03

Write a proof receipt

Commands, exit codes, timing, output digests, and every path touched. A stranger can inspect it. The output itself is never stored.

04

Remember decisions

An append-only ledger of choices, rejections, constraints, and assumptions. Change your mind; never erase the trail.

05

Undo without git

Content-addressed checkpoints before every mutation. Restore edits, delete files the call created, and refuse to guess when the sweep was truncated.

06

Push back on scope

Destructive verbs, credentials plus an outbound action, surprise dependencies, three objectives in one. It asks before it acts.

ALSO

Context compaction · GitHub and Vercel account switching · local Ollama · keyless default · proof receipts on every turn.

Proof / 02

A GREEN CHECK IS NOT EVIDENCE.
THIS IS.

Other agents say done. Weaver writes a file with commands, exit codes, hashes, and the paths it touched. The output isn’t stored — a failing test can print a secret. The digest binds the receipt to what ran.

The gate is deterministic

Canary judges every change in-process from a hash-pinned engine. There is no flag that lets the agent approve its own work.

Self-authored checks are capped

If the turn edited a test, a test config, or the check command, the result is partial. A green run you authored is not independent evidence.

A human signs, or it stays blocked

The receipt is the permission slip. Weaver can be judged; it cannot sign its own.

“Trust is a file you can read.”
